# Thaa v0.1.1 — Selected Tester Guide

Thaa `v0.1.1` is the current **Early Preview** for selected testers. It fixes
the invalid macOS application-bundle signature in `v0.1.0`. It is not a
stable, production-ready, warning-free, or comprehensively validated release.

Download only from the [official Thaa v0.1.1 GitHub Pre-release](https://github.com/thg1rb/thaa/releases/tag/v0.1.1).
The release includes `SHA256SUMS.txt`; checking the checksum is recommended,
especially for these unsigned packages.

## macOS — Apple Silicon, macOS 15+

The DMG is validly ad-hoc signed, but it is not Developer ID signed or
notarized. macOS may show a verification warning. On the user's validated
machine, the warning said Apple could not verify that Thaa is free of malware;
the supported per-app flow was **System Settings → Privacy & Security → Open
Anyway**, after which Thaa launched. Wording and available controls may vary
by macOS version.

Install by opening the official DMG and copying `Thaa.app` to Applications.
If you see a specific malware/XProtect block or “Thaa is damaged and can’t be
opened,” stop and report the message. Do not disable Gatekeeper, remove
quarantine broadly, change SIP, or weaken system security. Remove the app from
Applications to uninstall it.

## Windows — x64, Windows 11

The NSIS installer is unsigned. SmartScreen may warn, and Smart App Control or
organization policy may block installation. If a standard Windows UI offers
continuation, proceed only if you trust the official download. If policy
blocks it, stop and report the Windows version/edition and message; do not
disable SmartScreen, Smart App Control, antivirus, or managed policy. Use
Windows Settings → Apps → Installed apps to uninstall Thaa.

## Core test — about 10–20 minutes

Check installation, first launch, tray access, Runtime Inspector, listener
discovery, Search by process name and port, Refresh, Copy/Open, and
quit/relaunch. Try uninstall/reinstall where practical. For process actions,
inspect the process first and use only a safe disposable process you started
for testing. Stop and Force Stop can terminate running software; Force Stop is
destructive. Do not target system-critical processes, security tools,
login/session infrastructure, or applications with unsaved work.

Windows currently does not provide Working Directory or consequent Project
Root metadata, and generic graceful Stop is unsupported. Interactive Windows
clean-machine validation remains limited; those testers can provide useful
environment-specific installation feedback.

Report ordinary issues at [GitHub Issues](https://github.com/thg1rb/thaa/issues)
using the [v0.1.1 tester feedback template](v0.1.1-tester-feedback-template.md).
Include platform, OS version, and architecture; avoid private process names,
PIDs, command lines, account names, and filesystem paths. Report security
issues using [SECURITY.md](../../SECURITY.md).
