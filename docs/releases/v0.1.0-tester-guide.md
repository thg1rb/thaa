# Thaa v0.1.0 — selected tester guide

**Status:** Published Early Preview tester guide. Use the official GitHub
Pre-release linked below; do not use internal Actions candidate artifacts as
public downloads.

Thaa `v0.1.0` is an **Early Preview** for selected testers. It is not stable,
production-ready, warning-free, or comprehensively validated across all
environments. Tester reports provide the interactive Gate B evidence after
publication; this guide does not imply those checks have already passed.

## Before installing

Download only from the official [Thaa v0.1.0 GitHub Pre-release](https://github.com/thg1rb/thaa/releases/tag/v0.1.0).
Verify the published SHA-256 manifest when practical. The released filenames
and SHA-256 values are:

- macOS Apple Silicon, macOS 15+: `Thaa_0.1.0_aarch64.dmg` —
  `4365f2a0d91ef5865f3aaad953fdce004c80ed8425272af9ad2c5af8fb438297`
- Windows 11 x64: `Thaa_0.1.0_x64-setup.exe` (NSIS) —
  `f2503274b4a6d432b27c3203029f37126791ccf851f7900d6f092c45a9944073`

The macOS build is not Developer ID signed or Apple-notarized. macOS may warn
or block first launch. If you trust the official download and have verified
its checksum, use only a normal per-application approval flow offered by
macOS, such as reviewing the blocked app in System Settings → Privacy &
Security. If no normal approval option is offered, stop and report the message.
Do not disable Gatekeeper, SIP, or security protections globally.

The Windows installer is unsigned. Microsoft Defender SmartScreen may warn;
Smart App Control or organization-managed policy may block installation
entirely. If Windows offers a normal per-app continuation, proceed only if you
trust the official download and checked its checksum. If policy blocks it,
stop and report the environment and message. Do not disable SmartScreen, Smart
App Control, antivirus, or organization policy.

Do not install a local development build or run Thaa as administrator/root.

## Level 1 — Core test (about 10–20 minutes)

1. Download the package for your OS; verify the checksum if practical.
2. Install and launch Thaa; note any first-launch security message.
3. Check the tray/menu-bar entry and open the Runtime Inspector.
4. Confirm visible local listeners and process identity where available.
5. Search by process name and by exact port; clear Search; Refresh.
6. Try Copy URL, Copy Port, Copy PID, and Open URL when a suitable local
   listener is available.
7. Inspect a process before using Stop or Force Stop. If testing process
   control, use a safe disposable process that you started for this purpose.
   Do not target OS-critical processes, security software, login/session
   services, or applications with unsaved work. Force Stop is destructive.
8. Quit and relaunch. Try uninstall/reinstall if convenient.
9. Report results with the [feedback template](v0.1.0-tester-feedback-template.md).

## Level 2 — Extended functional test (optional, about 30–60 minutes)

Try multiple listener appearances/disappearances, repeated Refresh, different
search queries and capitalization, multiple process types, Working Directory
and Project Root where supported, tray/window interactions, native/fallback
icons, scrolling/layout, and repeated Copy/Open operations. Note stale or
duplicated listeners, failed refreshes, crashes, hangs, and any unexpected
process action.

## Level 3 — Long-run stability (optional power-tester test, about 8 hours)

This is optional; testers do not need to interact continuously. At a few
convenient checkpoints, observe CPU/memory, Refresh, Search, tray/window
behavior, and whether listener data stays current. Record crashes, hangs,
unexpected resource use, duplicate/stale listeners, or refresh failures in the
feedback template. The eight-hour duration is a test method, not a new product
performance threshold.

## Known limitations

- The first macOS package targets Apple Silicon on macOS 15 or later. It is
  unsigned/ad-hoc and not notarized; Gatekeeper may warn or block first launch.
- The first Windows package targets Windows 11 x64 and uses an unsigned NSIS
  installer. SmartScreen may warn; Smart App Control or managed policy may
  block it.
- The current Windows provider does not expose Working Directory, so Project
  Root is also unavailable there.
- Generic graceful Stop is not supported on Windows. Force Stop is the
  supported termination action where available and requires confirmation.
- Interactive Windows clean-machine validation and Windows soak have not been
  performed by the project; tester evidence is welcome.
- Linux is not a release target.

## Reporting

Report ordinary bugs through [GitHub Issues](https://github.com/thg1rb/thaa/issues).
Use the project's [security policy](../../SECURITY.md) for security issues.
For installation problems, include OS version/edition, architecture, and the
security warning/block behavior. Do not include private process names, PIDs,
command lines, account names, or filesystem paths. Avoid attaching crash dumps
or full process command lines. Do not bypass organization policy or weaken OS
security to run the preview.
