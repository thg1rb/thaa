This retest is mandatory before publishing v0.1.1 because the published
v0.1.0 app bundle failed strict signature validation. Use only the exact
macOS DMG downloaded from the accepted GitHub Actions candidate run. Do not
substitute a local rebuild.

## Verify and install

1. Download `macos-aarch64` from the linked Actions run and extract
   `Thaa_0.1.1_aarch64.dmg`. Confirm the filename and source/run identity above.
2. Quit any running Thaa. If the old `/Applications/Thaa.app` exists, remove
   that app through Finder before installing the candidate. This does not
   require deleting unrelated user data.
3. From the download directory, verify the candidate checksum:

   ```bash
   shasum -a 256 Thaa_0.1.1_aarch64.dmg
   ```

   It must equal the expected SHA-256 above and match the run's
   `SHA256SUMS.txt`. If it does not, stop and do not open the DMG.

4. Open the DMG and copy `Thaa.app` into `/Applications` using Finder. Do not
   use a local build or modify the app before checking it.
5. Before launching, run:

   ```bash
   codesign --verify --deep --strict --verbose=4 /Applications/Thaa.app
   ```

   **Expected:** exit code `0`, with no resource-seal or Info.plist coverage
   errors. If this fails, stop and report the output; do not remove quarantine
   or bypass the signature failure.

6. Attempt first launch through the normal macOS UI. Record the actual
   Gatekeeper behavior. The app remains ad-hoc signed and not notarized, so a
   normal per-app security approval may still be required. Do not disable
   Gatekeeper or other system security globally. If an explicit XProtect or
   malware block appears, stop and report it; do not attempt to override it.
7. If launch is acceptable, check tray access, Runtime Inspector, listener
   discovery, Search, Refresh, process metadata, Copy/Open, and safe process
   actions. Quit, relaunch, uninstall, and reinstall where practical.
