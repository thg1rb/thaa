# v0.1.0 Release Credential Checklist

This checklist describes configuration required by
`.github/workflows/release.yml`. Never commit credentials, print them in CI, or
paste secret values into issues or work records. The repository currently has
no release environment, GitHub Actions secrets, or signing credentials.

## GitHub environments

Create two GitHub repository environments before running a release:

| Environment       | Protection                              | Allowed ref              | Purpose                                                                      |
| ----------------- | --------------------------------------- | ------------------------ | ---------------------------------------------------------------------------- |
| `release`         | Required reviewer; branch rules enabled | `main` workflow dispatch | Restricts macOS signing/notarization secrets to the trusted release workflow |
| `release-publish` | Required reviewer; branch rules enabled | `main` workflow dispatch | Approval gate for publishing the GitHub pre-release                          |

Do not allow pull-request refs. Dispatch the workflow definition only from
`main`. Candidate mode resolves the current `develop` commit to an immutable
SHA in the no-secrets validation job, prints that SHA in the job summary, and
builds only that commit. Before approving the protected `release` environment,
the reviewer must compare the displayed SHA with the reviewed `develop` state.
Final mode accepts only an existing `v0.1.0` tag, which the no-secrets
validation job verifies is reachable from `main` before the macOS signing job
starts. Immediately before release creation, the publishing job fetches the tag
again and verifies that it still points to the validated SHA. Before any final
publication, configure a repository tag ruleset for `v0.1.0` that restricts
creation to release maintainers and blocks tag updates and deletion. Do not
approve publication until this immutable-tag protection is active.

## macOS Developer ID signing and notarization

| Item                                                  | How to obtain / configure                                                                                                                                                                    | GitHub name                                                                                                                                                                    | Needed for                                                               |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| Apple Developer Program membership                    | Enroll through [Apple Developer Program](https://developer.apple.com/programs/whats-included/); Apple currently lists USD $99/year (regional pricing may vary).                              | Account is configured outside Actions                                                                                                                                          | Developer ID distribution; mandatory for the intended macOS artifact     |
| Developer ID Application certificate with private key | Create in Certificates, Identifiers & Profiles and export certificate plus private key as a password-protected `.p12`. Encode the file as one-line base64 locally. Do not commit the `.p12`. | Environment secret `APPLE_CERTIFICATE` (base64 P12)                                                                                                                            | Signed macOS DMG; mandatory                                              |
| P12 import password                                   | Choose when exporting the `.p12`; store only in the protected environment.                                                                                                                   | Environment secret `APPLE_CERTIFICATE_PASSWORD`                                                                                                                                | Signed macOS DMG; mandatory                                              |
| Signing identity                                      | Exact Developer ID Application identity name as shown by Keychain/codesign.                                                                                                                  | Environment variable `APPLE_SIGNING_IDENTITY`                                                                                                                                  | Signed macOS DMG; mandatory                                              |
| Apple Team ID                                         | Team identifier from the Apple developer account.                                                                                                                                            | Environment variable `APPLE_TEAM_ID`                                                                                                                                           | Workflow verifies the produced signature belongs to this team; mandatory |
| App Store Connect API key                             | Create a key with the role/access required for notarization in App Store Connect. Download the `.p8` private key once and keep it secure.                                                    | Environment variable `APPLE_API_KEY` for Key ID; environment variable `APPLE_API_ISSUER` for Issuer ID; environment secret `APPLE_API_KEY_P8_BASE64` for base64 `.p8` contents | Notarization and stapling; mandatory                                     |

The workflow uses API-key authentication. It does not require an Apple ID
password or app-specific password. The runner writes the decoded API key only
under its temporary directory with owner-only file permissions. Tauri imports
the certificate for the build; no persistent keychain or signing material is
stored in the repository. The intended signed/notarized macOS distribution is
blocked until these credentials and protected environments exist and a real
candidate passes signature, notarization, stapling, and Gatekeeper checks.

## Windows signing

The approved R001 choice is an **unsigned Windows 11 x64 NSIS installer for
selected testers**, with explicit SmartScreen and Smart App Control disclosure.
No Windows signing credential is required for this chosen closed-alpha path.
Smart App Control or enterprise policy may block the package entirely; never
recommend disabling those protections.

Authenticode can be added in a later release decision. It would require a
trusted code-signing certificate and private key (commonly supplied as a
password-protected PFX), its password, and a timestamp service. Certificate
prices and issuance rules vary by provider. No certificate or signing secrets
are currently configured. This absence does not block the user-approved
unsigned selected-tester package.
