# W008.2 — CI Performance Hardening

## Status

Done on merge ([measurement evidence PR #22](https://github.com/thg1rb/thaa/pull/22);
CI implementation integrated by [PR #21](https://github.com/thg1rb/thaa/pull/21)).
Integrated `develop` release-profile cache seeding and three consecutive warm
manual runs passed on macOS, Windows, and Shared Quality.

## Objective

Reduce CI feedback latency without weakening W004 checks or the native macOS
and Windows validation established by W008.1. Establish measured Cargo cache
and build-profile behavior before W009.

## Scope

- Add isolated Rust/Cargo caches for Shared Quality, macOS, and Windows jobs.
- Cache the pinned RustSec audit tool and dependencies while continuing to run
  both target audits on every workflow run.
- Use a debug Tauri no-bundle build for PR validation and retain release
  no-bundle builds on integrated `develop` and manual runs.
- Record cold-cache, post-merge cache-seed, and three warm workflow timings.
- Document the CI design and the work-item closeout convention.

## Out of Scope

W009, product functionality, Bun migration, sccache, CI gate removal, release
publishing/signing, branch protection, dependency automation, and changes to
the frozen requirements baseline.

## Requirements

Establishes validation infrastructure supporting cross-platform consistency,
reliability, maintainability, and dependency security. No functional
requirement is implemented or changed.

## Dependencies

W008.1 is integrated. W004 governs test evidence and security checks; W005.1
governs formatter/tooling ownership; W008 provides the macOS native integration
tests.

### Cache and build-profile strategy

Use `Swatinem/rust-cache` v2.9.2 pinned to immutable commit
`6323deb102c322ba6fcbdcafc7e3dddab59af2b6`. Its workspace is `src-tauri ->
target`; cache keys are separated by OS/architecture and toolchain and include
Cargo manifests/lockfiles. Shared Quality additionally caches the pinned
`cargo-audit` binary and its dependencies. Caches are optimization only; all
required commands still execute after a miss. Trusted pushes to `develop`
save the develop-scoped caches. Same-repository PRs can save only to their
GitHub PR merge-ref cache, isolated from `develop` and other PRs; fork PRs do
not save a cache. Manual runs only restore. This allows cold and warm PR
profile measurements before merge without creating a develop-scope write path
for PR code.

PRs retain Rust fmt, Clippy, all Rust tests, native macOS tests, frontend
quality checks, dependency audits, and documentation checks. Only the Tauri
build profile changes on PRs to `--debug --no-bundle`; `develop` and manual
workflow runs retain `--no-bundle` release-profile builds. This preserves
release compilation evidence while reducing PR compilation cost. No required
gate is moved after merge.

Rust compilation uses distinct Cargo profiles for checks/tests and the Tauri
release build. A Cargo cache can reuse compatible dependencies/artifacts but
does not make the debug/test and release profiles identical. Do not add
sccache unless warm-run measurements show ordinary caching leaves a material
Rust compilation bottleneck.

### Cache validation plan and PR measurements

PR cold and warm evidence is [run 37096292899](https://github.com/thg1rb/thaa/actions/runs/37096292899),
head `0b2ec8adde2ddb4cb838e09dc051a3b7bcd760e3`. Attempt 1 was a cache miss
and saved same-PR cache entries; attempts 2–4 were three consecutive warm
runs. A subsequent fifth attempt on the same head also passed. Logs confirm
cache restores on Ubuntu, macOS, and Windows; the audit binary is reused; W008
macOS native tests still execute; and both native PR jobs run the debug Tauri
build. Cache timings include restore overhead and vary with runner load.

| Platform / job | Baseline release | Cold PR debug | Warm PR debug runs (attempts 2–4) | Warm median |
| -------------- | ---------------: | ------------: | --------------------------------- | ----------: |
| macOS native   |            5m10s |         2m33s | 1m39s, 1m42s, 1m53s               |       1m42s |
| Windows native |            9m52s |         5m17s | 2m07s, 2m41s, 2m16s               |       2m16s |
| Shared Quality |            3m32s |         3m47s | 34s, 43s, 49s                     |         43s |

Baseline Tauri builds were release-profile; PR builds are debug-profile, so
the total-job comparison includes both profile and cache changes. Within the
same PR debug profile, median Clippy/tests/Tauri step times were 16s/25s/29s
on macOS and 23s/16s/18s on Windows. Cold runs took 46s/44s/22s and
103s/77s/20s respectively. Shared Quality's pinned `cargo-audit` install took
178s cold and under one second in each of the three warm runs. Median cache
restore times were 8s on macOS, 24s on Windows, and 4s in Shared Quality. All
required checks passed on these runs.

Ordinary Cargo caching materially reduces warm Clippy/test times and removes
repeated `cargo-audit` compilation. PR debug builds complete quickly, but
release-profile performance remains unmeasured. Do not claim a release-build
speedup until the `develop` measurements are recorded. After merge, the trusted
`develop` push must seed release caches; run three sequential manual
`develop` workflows and record release-profile Clippy, tests, Tauri, cache
restore/save, and job totals in the remaining section.

controlled-listener tests executed on all three runs. Manual runs are readers

Job totals include runner setup, cache download, queue/host variability, and
cleanup. The hosted arm64 macOS runner emitted a capacity warning, and the

with a cache hit. Median step timings were:

| Platform       | Cache restore | Clippy | Tests | Tauri release build |
| -------------- | ------------: | -----: | ----: | ------------------: |
| macOS          |           23s |    11s |   11s |                 95s |
| Windows        |           37s |    34s |   12s |                 84s |
| Shared Quality |            5s |      — |     — |                   — |

The measured warm Tauri release build medians decreased from 201s to 95s on
macOS and from 331s to 84s on Windows. Warm total job medians decreased from
the W008.1 baseline of 5m10s to 2m55s on macOS (43% lower), and from 9m52s to
3m59s on Windows (60% lower). The baseline is a single run, so these
percentages are observations rather than performance guarantees. The
first-run Windows median is not meant to represent all runner load conditions.

The cache action log shows a full macOS target cache of approximately 662 MB
restored at around 52.6 MB/s; the restore itself took 23s in the third manual
run. Windows target-cache restoration took a median 37s. Cache download cost
is material but still below the compilation time it avoids. Cache misses
remain correct and reproducible: every command ran in the cold seed and all
checks passed.

Shared Quality's first integrated audit run spent 2m18s total; subsequent
warm totals were 47s, 34s, and 39s. Its exact pinned `cargo-audit` version and
RustSec and pnpm audits executed on every run. The audit binary was present
from the trusted seed and its version check was reused; audit execution is
not skipped. No sccache is needed at this stage: warm Clippy and test steps
were 7–34s and Tauri release build medians were 84–95s. The remaining largest
cost is the Tauri application build plus cache restore and platform runner
setup, not repeated dependency compilation or pnpm.

integration evidence; no follow-up PR is required solely to edit status or
record the merge hash.

## Security Considerations

Workflow permissions remain `contents: read`; no project secrets are required.
Actions stay pinned to immutable upstream commit SHAs. Same-repository PR runs
write only the isolated PR merge-ref cache; fork PRs cannot save, and no PR can
write the trusted `develop` cache. Caches contain build dependencies/artifacts,
not credentials. Cache availability never controls whether validation runs.
`cargo-audit` remains exact-version pinned, and RustSec/pnpm audits continue to
run rather than being skipped on cache hits. The PR event remains
`pull_request`, not `pull_request_target`.

## Platform Considerations

Rust caches are distinct by runner OS/architecture/toolchain and use the
`src-tauri` Cargo workspace. macOS 15 arm64 continues running the controlled
W008 listener tests; Windows Server 2025 x64 continues native compilation and
tests. Neither platform's native checks are moved exclusively to post-merge.
Manual and integrated `develop` runs use release-profile Tauri builds.

## Known Limitations

- One baseline workflow run does not quantify normal timing variance.
- Cargo profile separation means cached test/debug artifacts do not eliminate
  release-profile Tauri compilation.
- Tauri release builds and cache restores remain the largest individual
  components in native jobs; their observed timings vary with hosted runner
  capacity and are not guaranteed service levels.
- GitHub branch protection remains unconfigured as recorded by W008.1.
- Windows native provider behavior remains unimplemented and belongs to W009.
