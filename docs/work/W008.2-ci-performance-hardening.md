# W008.2 — CI Performance Hardening

## Status

In progress. Final status will be recorded as `Done on merge` with the reviewed
PR link after the required cache and timing evidence is available.

## Objective

Reduce CI feedback latency without weakening W004 checks or the native macOS
and Windows validation established by W008.1. Establish measured Cargo cache
and build-profile behavior before W009.

## Scope

- Add isolated Rust/Cargo caches for Shared Quality, macOS, and Windows jobs.
- Cache the pinned RustSec audit tool and dependencies while continuing to run
  both target audits on every workflow run.
- Use a debug Tauri no-bundle build for PR validation and retain release
  no-bundle builds on integrated `develop` and manual runs.
- Record cold-cache, post-merge cache-seed, and three warm workflow timings.
- Document the CI design and the work-item closeout convention.

## Out of Scope

W009, product functionality, Bun migration, sccache, CI gate removal, release
publishing/signing, branch protection, dependency automation, and changes to
the frozen requirements baseline.

## Requirements

Establishes validation infrastructure supporting cross-platform consistency,
reliability, maintainability, and dependency security. No functional
requirement is implemented or changed.

## Dependencies

W008.1 is integrated. W004 governs test evidence and security checks; W005.1
governs formatter/tooling ownership; W008 provides the macOS native integration
tests.

### Cache and build-profile strategy

Use `Swatinem/rust-cache` v2.9.2 pinned to immutable commit
`6323deb102c322ba6fcbdcafc7e3dddab59af2b6`. Its workspace is `src-tauri ->
target`; cache keys are separated by OS/architecture and toolchain and include
Cargo manifests/lockfiles. Shared Quality additionally caches the pinned
`cargo-audit` binary and its dependencies. Caches are optimization only; all
required commands still execute after a miss. Trusted pushes to `develop`
save the develop-scoped caches. Same-repository PRs can save only to their
GitHub PR merge-ref cache, isolated from `develop` and other PRs; fork PRs do
not save a cache. Manual runs only restore. This allows cold and warm PR
profile measurements before merge without creating a develop-scope write path
for PR code.

PRs retain Rust fmt, Clippy, all Rust tests, native macOS tests, frontend
quality checks, dependency audits, and documentation checks. Only the Tauri
build profile changes on PRs to `--debug --no-bundle`; `develop` and manual
workflow runs retain `--no-bundle` release-profile builds. This preserves
release compilation evidence while reducing PR compilation cost. No required
gate is moved after merge.

Rust compilation uses distinct Cargo profiles for checks/tests and the Tauri
release build. A Cargo cache can reuse compatible dependencies/artifacts but
does not make the debug/test and release profiles identical. Do not add
sccache unless warm-run measurements show ordinary caching leaves a material
Rust compilation bottleneck.

### Cache validation plan

The task PR's first run is the cold-cache observation; it should report
misses and execute every command. Same-repository PR runs then seed only that
PR's isolated cache, allowing repeated PR runs to measure warm debug-profile
behavior before merge. After merge, the trusted `develop` push seeds the
develop-scoped cache using the release build. Run three sequential manual
`develop` workflows to measure release-profile warm hits for Clippy, tests,
Tauri, cache restoration/save, and total job durations on both platforms.
Record run links and step durations below.

### Work-item closeout convention

Record `Status: Done on merge` and the implementation PR link in this work
item on the task branch after review and acceptance gates pass. The status is
effective when that PR merges. The PR and `develop` history preserve traceable
integration evidence; no follow-up PR is required solely to edit status or
record the merge hash.

## Security Considerations

Workflow permissions remain `contents: read`; no project secrets are required.
Actions stay pinned to immutable upstream commit SHAs. Same-repository PR runs
write only the isolated PR merge-ref cache; fork PRs cannot save, and no PR can
write the trusted `develop` cache. Caches contain build dependencies/artifacts,
not credentials. Cache availability never controls whether validation runs.
`cargo-audit` remains exact-version pinned, and RustSec/pnpm audits continue to
run rather than being skipped on cache hits. The PR event remains
`pull_request`, not `pull_request_target`.

## Platform Considerations

Rust caches are distinct by runner OS/architecture/toolchain and use the
`src-tauri` Cargo workspace. macOS 15 arm64 continues running the controlled
W008 listener tests; Windows Server 2025 x64 continues native compilation and
tests. Neither platform's native checks are moved exclusively to post-merge.
Manual and integrated `develop` runs use release-profile Tauri builds.

## Known Limitations

- One baseline workflow run does not quantify normal timing variance.
- Cargo profile separation means cached test/debug artifacts do not eliminate
  release-profile Tauri compilation.
- Warm cache evidence requires the `develop` push to seed a cache before the
  three manual warm runs.
- GitHub branch protection remains unconfigured as recorded by W008.1.
- Windows native provider behavior remains unimplemented and belongs to W009.
