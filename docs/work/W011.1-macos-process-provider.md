# W011.1 — macOS Process Provider

## Status

Done on merge — PR #26 passed review and required checks; integration is
pending.

## Objective

Implement the first native `ProcessProvider` behind W010 and validate it with a
controlled non-GUI process on macOS.

## Scope

- Implement requested-PID inspection in `platform::macos` using supported
  system utilities and the W006/W010 shared types.
- Report best-effort metadata with honest field availability.
- Detect process absence, zombie state, and observed identity changes around
  metadata collection.
- Add deterministic parser/normalization tests and controlled native tests for
  W010 and W011 compatibility.

## Out of Scope

Private Apple APIs, native FFI, `NSRunningApplication`, process enumeration,
Windows process inspection, process actions, Tauri IPC, frontend integration,
refresh coordination, project/Git/runtime detection, and resource metrics.

## Requirements

W011.1 establishes macOS provider evidence for FR-006 and supports explicit
disappearance/error handling relevant to FR-011. It does not complete
cross-platform or user-facing process inspection. `THAA-REQ-0.1` is unchanged.

## Dependencies

W006 process models, W010 `ProcessProvider`, W011 shared inspection, W003
platform boundaries, W004 security/testing guidance, and W008.2 native CI
lifecycle. Apply `rust-patterns` and `security-and-hardening`.

## Design Notes

### API feasibility

| Field                | Mechanisms evaluated                                                                         | Selected mechanism                                      | Support status                                              | Limitation                                                                             |
| -------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| PID / existence      | `ps` (`pid`, `state`)                                                                        | Direct `/bin/ps` query before and after metadata lookup | Available for requested PID when query succeeds             | Snapshot is an observation, not durable identity                                       |
| Name                 | `NSRunningApplication.localizedName`, `ps`, `lsof`                                           | `lsof` machine field `c`                                | Available when `lsof` returns an unambiguous process record | Kernel command name may be truncated; GUI app display names are not used               |
| Executable           | `NSRunningApplication.executableURL` (app only), `proc_pidpath` / `libproc`, argv[0], `lsof` | No executable source selected                           | `Unavailable(ProviderLimitation)`                           | AppKit source excludes general CLI; `libproc` is private; argv[0] is not authoritative |
| Start time           | `NSRunningApplication.launchDate` (app only), `ps lstart`; `proc_pidinfo`                    | `ps` `lstart`, normalized as UTC                        | Available at one-second resolution                          | Same PID/name/start second cannot conclusively rule out rapid PID reuse                |
| Structured arguments | `ps` command text, `NSRunningApplication`, `libproc`                                         | No source selected                                      | `Unavailable(ProviderLimitation)`                           | Human-readable command text cannot reconstruct argv boundaries; no private API         |
| Working directory    | `lsof` cwd file record; `proc_pidinfo`/fd APIs                                               | `lsof -F0... -d cwd`                                    | Available when readable and output is unambiguous           | Permission and sandbox/distribution behavior varies                                    |

Apple documents `NSRunningApplication` as information for one application, so
it is not used as a universal process source ([class reference](https://developer.apple.com/documentation/appkit/nsrunningapplication)).
The SDK `libproc.h` header and [Apple DTS guidance](https://developer.apple.com/forums/thread/837541)
identify libproc interfaces as private/unstable; no such API is called.
`/bin/ps` and `/usr/sbin/lsof` are standard system
utilities and are invoked directly with fixed option vectors, numeric PID,
cleared environment, and bounded time/output. No shell is involved. Output is
parsed as bytes; lsof escape-like representations are treated as unavailable
rather than decoded lossily.

The provider takes snapshots before and after `lsof`. Missing PID, zombie
state, or a changed PID/start-time/state tuple is `ProcessDisappeared`. A
field-specific lsof denial or limitation remains successful `ProcessInfo`
when `ps` establishes the process. Executable and command arguments remain
unavailable. No process name, path, or argv is inferred. If platform capability
reporting is added later, command-line support should be `Unsupported` for this
provider; working-directory support is available on a best-effort basis, with
per-process restrictions carried by `FieldAvailability`.

Direct signed/notarized distribution has not been exercised, so compatibility
is not claimed by this work. App Sandbox inheritance and Mac App Store
suitability have not been validated. The product distribution channel remains
unspecified; this work makes no distribution approval claim. Apple states that Mac App
Store distribution requires App Sandbox ([App Sandbox documentation](https://developer.apple.com/documentation/security/app-sandbox)); child processes inherit sandbox restrictions ([archived entitlement guidance](https://developer.apple.com/library/archive/documentation/Miscellaneous/Reference/EntitlementKeyReference/Chapters/EnablingAppSandbox.html)).

## Security Considerations

System-derived output is untrusted. Invocation is shell-free and uses fixed
arguments plus a numeric `ProcessId`; inherited environment is cleared.
Subprocess time and combined capture are bounded. Raw output and stderr are
not logged or included in provider errors. No elevation, private API, FFI, or
destructive operation is used. Process metadata may still contain sensitive
local information, so W011.1 adds no metadata logging.

## Platform Considerations

Implementation is compiled only in the macOS platform module. Native evidence
is local macOS 27.0 arm64; hosted macOS CI evidence is still required. Windows
remains unimplemented for process metadata; existing Windows CI is a
regression gate only. Sandbox and App Store behavior is unverified.

## Known Limitations

- Executable path and structured command arguments are intentionally
  unavailable without an acceptable public source.
- Start time is second-resolution. Before/after comparison reduces ordinary
  races but cannot prove durable identity or authorize an action.
- `lsof`/`ps` sandbox, signed app, and App Store distribution compatibility is
  not established.
- Native permission behavior for protected processes was not forced in a
  destructive or privileged test.
- Other macOS releases and architectures require CI/native evidence.
