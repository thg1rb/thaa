# W012.1 — macOS Process Controller

## Status

Done on merge.

## Objective

Implement the first native `ProcessController` against the unchanged W012.0
identity-bound contract, with macOS Graceful Stop (`SIGTERM`) and Force Stop
(`SIGKILL`).

## Scope

- Reuse the SDK-backed `sysctl(KERN_PROC_PID)` start-time identity query used
  by `MacOSProcessProvider`.
- Add `MacOSProcessController` and macOS platform capability reporting.
- Extend the existing macOS C shim with one fixed-signal call that captures
  and classifies `errno` immediately.
- Add deterministic conversion/result-mapping tests and native tests against
  test-owned `/bin/sleep` children.
- Update action architecture, security, test, and requirement traceability.

## Out of Scope

No Windows controller, Tauri process/action command, frontend controls,
automatic wait/retry/escalation/elevation, process-group/child-tree/bulk
signals, self-termination policy, or distribution/sandbox certification.

## Requirements

Implements the macOS controller foundation for FR-008 and FR-009 under the
W012.0.1 clarification. Graceful Stop requests `SIGTERM`; Force Stop requests
`SIGKILL`. They remain separate and capability-gated. Acceptance of a signal
request is not confirmation that the process exited.

## Identity Safety Model

`ProcessController::request` accepts only `ProcessActionTarget`. The adapter
checks positive, representable PID, reads fresh start-time identity through the
shared sysctl helper, and requires exact PID/start-time match before action.
If a target includes executable-path evidence, current macOS inspection cannot
revalidate it and the shared validator returns `IdentityUnavailable`; the
controller fails closed. Missing process/zombie before the signal returns
`AlreadyExited`. No full `ProcessProvider` inspection or `kill(pid, 0)` is used.

## Native Action Design

`MacOSProcessController` maps `GracefulStop` only to `SIGTERM` and `ForceStop`
only to `SIGKILL`. The extended C shim accepts a checked PID and one of two
fixed action selectors; it rejects nonpositive PID values and maps native
results to bounded statuses. A compile-time assertion checks that macOS
`pid_t` and the checked Rust `i32` have the same width. The C shim is compiled
only for macOS through the existing `cc` build dependency. No new runtime
dependency is added.

The controller's capability provider reports command-line metadata unsupported,
working-directory metadata supported, and graceful/force actions supported.
These platform-wide values do not promise access to a particular process.
There is no Tauri composition or UI action path in this work item.

## Signal Semantics

The fresh sysctl read and positive-PID signal call remain separate operations.
The controller selects the fixed signal before revalidation and performs only
the identity comparison between the fresh query and the C shim call. A zero
shim result returns `Requested`; the controller never waits for process exit
or escalates SIGTERM to SIGKILL. `ESRCH` maps to `AlreadyExited` without retry.

## Error Mapping

| Native condition                                | Shared result            |
| ----------------------------------------------- | ------------------------ |
| `sysctl` establishes absent/zombie process      | `Ok(AlreadyExited)`      |
| Start time or PID differs                       | `IdentityMismatch`       |
| Required identity cannot be revalidated         | `IdentityUnavailable`    |
| Signal accepted                                 | `Ok(Requested)`          |
| `ESRCH` during `kill`                           | `Ok(AlreadyExited)`      |
| `EPERM`                                         | `PermissionDenied`       |
| `EINVAL`, other errno, or malformed shim status | `OperatingSystemFailure` |
| Nonpositive or unrepresentable PID              | `InvalidTarget`          |

Raw errno values and native text are not exposed.

## Residual Race

macOS identity validation (`sysctl`) and action (`kill`) are not atomic. A
process can theoretically exit and its PID be reused in the narrow interval
between them. The controller minimizes the interval and documents this
residual; it does not claim to eliminate PID reuse. The action always passes a
strictly positive checked PID, so process-group and broad `kill` semantics are
unreachable.

## Controlled-process Test Strategy

Each destructive integration test spawns its own `/bin/sleep` child and uses
the returned `Child` PID to inspect, target, and clean it up. Graceful and force
tests use separate children and verify the observed exit signal. The mismatch
test changes only the expected start time, verifies `IdentityMismatch`, then
verifies the child remains alive before RAII cleanup. The already-exited test
stops/reaps its child through the fixture and verifies `AlreadyExited`.
Bounded waits prevent test hangs. Tests never target Thaa, the test runner, or
an unrelated process. Native permission denial is not induced against a
system process; its stable mapping is covered deterministically.

## Security Considerations

The C shim accepts only fixed signal selectors and positive PIDs. Rust uses a
checked conversion from the full-range shared `u32` PID to `i32`; the C build
asserts `pid_t` width. `errno` is captured immediately after failed `kill(2)`.
Identity mismatch and unavailable evidence fail closed; no signal-zero check,
shell, `/bin/kill`, privilege elevation, raw metadata logging, or native error
text is used. Tests can signal only their own child processes.

## Platform Considerations

macOS supports both generic actions subject to per-process permissions. Its
PID-to-signal race remains residual. Windows generic Graceful Stop remains
unsupported, and Windows Force Stop is not implemented here. Hosted macOS CI
uses macOS 15 arm64; local evidence is macOS 27.0 arm64. App Sandbox, Mac App
Store, notarized distribution, and other OS versions are not validated.

## Known Limitations

- The check-to-signal PID reuse interval cannot be eliminated by this public
  sysctl-plus-PID-signal design.
- Process actions are not composed into Tauri or exposed in the UI.
- Live permission-denial behavior and distribution sandbox compatibility are
  not validated.
- Windows force-stop and user-facing cross-platform action flow remain future
  work.
